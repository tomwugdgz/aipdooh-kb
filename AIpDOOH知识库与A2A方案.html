一、总体架构：双引擎 + A2A 智能体层

针对「千亿原始 / 十亿知识 / 全本地 / A2A」四个约束，采用 双数据引擎 设计：海量原始数据进湖仓（分析/特征/按需检索），精炼知识进向量+图（RAG 实时检索）；上层由 A2A 智能体层 统一调度。整体 8 层：

① 接入层
媒体案例库 / DSP·ADX 投放日志 / 公司知识（Wiki·合同·玩法沉淀），Kafka 事件总线
② 湖仓层
Iceberg + MinIO + Spark/Flink + ClickHouse，扛千亿级原始与聚合特征
③ 知识加工层
解析→清洗→分块→媒体域元数据→实体/关系抽取，异步流水线
④ 知识存储层
Milvus(分布式) + NebulaGraph + PostgreSQL + Redis + MinIO
⑤ 知识计算层
Query改写→向量+BM25+图 混合召回→融合→Rerank→ACL过滤
⑥ A2A 智能体层
Agent Runtime(自研编排) + A2A协议适配 + 管理Agent调度领域智能体
⑦ 知识服务层
API网关(多租户/ACL/审计) + RAG问答 + Agent对话 + 管理后台
⑧ 运营管理
生命周期/版本/增量更新/评测(RAGAS)/反馈闭环/看板

二、数据接入与湖仓（扛千亿级原始数据）

2.1 数据源与连接器

数据源内容接入方式量级
媒体案例库 / 点位库屏位、商圈、屏型、覆盖、历史案例、创意JDBC/API 批+增量千万~亿级
DSP / ADX 投放日志播放、曝光、竞价、排期、转化Kafka 流 + 对象存储批量千亿级行
公司知识沉淀Wiki、合同、销售玩法、复盘、培训连接器批采 + Webhook百万~千万文档

2.2 湖仓选型（全本地）

  • 对象存储：MinIO（S3 兼容，本地部署），存原始日志与原文。
  • 表格式：Apache Iceberg（ACID、隐藏分区、时间旅行，利于增量更新与回溯）。
  • 计算：Spark（批量 ETL，清洗/特征/聚合）、Flink（投放日志实时入湖）、Trino（即席查询）。
  • OLAP：ClickHouse（投放日志的毫秒级聚合分析，支撑数据 Agent 即时问答）。
  • 作用：千亿级原始数据不直接进向量库；湖仓负责「全量留存 + 特征/聚合 + 冷知识按需检索后即时向量化」。

三、知识加工与存储（十亿级 chunk 的分布式方案）

3.1 加工流水线

工序户外媒体域要点
解析案例PDF/合同/投放报告；marker/unstructured；表格与屏位结构保留
清洗去噪、去重、脱敏（客户名/合同金额走脱敏策略）
分块语义分块 512–1024 token + 重叠；媒体域元数据：城市/商圈/屏型/客户行业/时段/时效
抽取实体：点位/客户/行业/创意/Campaign；关系：投放于/转化于/竞品/地域，入图
向量化bge-m3 本地批量（GPU 集群），写入 Milvus

3.2 分布式存储

存储选型（本地）存什么 / 规模应对
向量库Milvus 分布式集群十亿级 chunk；按租户/业务分 collection 与 shard，副本+冷热分层
图库NebulaGraph实体-关系，分布式扛大规模图谱推理
关系库PostgreSQL（主）+ 可选 TiDB元数据/ACL/租户/审计/评测
缓存Redis热点问答、会话、嵌入缓存
对象MinIO原文与附件（与湖仓共用）
十亿级向量工程要点：① 分片（shard）按业务/租户；② 冷热分层——高频案例/近期投放进热集（高副本），历史冷知识走湖仓按需取；③ 批量嵌入用独立 GPU 集群 + 断点续传；④ 索引用 HNSW/DiskANN 平衡召回与内存。

四、知识计算：混合检索 + Rerank + 权限过滤

Query改写/扩展→ 向量召回(Milvus)→ BM25召回(PG/ES)→ 图召回(Nebula)→ RRF融合→ Rerank(bge)→ ACL过滤→ Top-K
  • Embedding：bge-m3（支持稠密+稀疏，天然适配混合检索），全本地。
  • 混合召回：向量补语义、BM25 保精确术语（如屏型编号/客户名）、图补关系推理。
  • Rerank：bge-reranker 交叉编码器，仅对召回 Top-N 重排，控成本。
  • ACL 过滤：检索结果按 tenant_id / dept / level 强制过滤，安全红线。

五、A2A 智能体管理层（AI 管理 A2A 系统）

采用 Google A2A 协议（AgentCard / Task / JSON-RPC over HTTP + 鉴权） 作为智能体互操作标准，内部用自研编排运行时做任务分解与调度。核心是一个管理 Agent 统筹多个领域智能体。

5.1 智能体编队

Agent职责依赖
管理 Agent（AI 管理 A2A）接收高层目标→拆解→经 A2A 派发→监控→聚合→护栏全部
知识 AgentRAG 问答，检索知识库/湖仓检索层
媒体规划 Agent基于案例与数据做点位/商圈/排期规划知识+数据
投放优化 AgentpDOOH 竞价/预算/频次优化湖仓+数据Agent
创意 Agent按屏型/受众生成或适配创意LLM
数据 Agent湖仓/ClickHouse 即席分析与归因湖仓
合规/客户 Agent合同、品牌安全、出域与权限校验ACL/审计

5.2 交互与治理

  • 对外互操作：每个 Agent 暴露 AgentCard（能力/端点/鉴权），经 A2A Task 协议通信，可被外部系统调用。
  • 内部编排：管理 Agent 用自研运行时做目标拆解、依赖编排、并行/串行调度、超时与重试。
  • 护栏：所有跨 Agent 动作经合规 Agent 校验；敏感操作需人工确认；全链路审计。

九、MVP 底层可运行框架脚手架

同目录 aipdooh-kb/ 是一个可本地零依赖运行的框架雏形：用 numpy 实现的内存向量检索做 fallback，使 ingest 与 query 在任意机器直接跑通；生产环境把 SimpleVectorStore 换成 MilvusVectorStore、把 MockEmbedder 换成 BgeEmbedder 即可。已含 A2A 运行时骨架（管理 Agent 派发到知识 Agent）。

# 本地直接跑（无需 GPU / 外部服务）
cd aipdooh-kb
python pipelines/ingest.py      # 写入示例户外媒体案例
python pipelines/query.py "某商圈 LED 大屏适合哪些行业投放？"

生产基础设施用 docker-compose.yml 一键起 Milvus / PostgreSQL / MinIO / Redis / NebulaGraph / vLLM。
