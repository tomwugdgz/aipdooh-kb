🧠 AI 知识系统：总结归类 · 底层逻辑 · 落地方案

综合两篇材料：腾讯《Agent 的上限，可能不在模型，而在团队知识》× Tom《我的知识库使用说明书（第二大脑）》

核心判断：企业级与个人级，是同一范式（LLM Wiki）的两个尺度

一句话结论

两篇材料讲的是组织级和个人级的同一件事：把"人写人读的仓库"升级成"人 + Agent 共读的供给系统"。底层逻辑高度一致——结构化、靠流程/投放沉淀、闭环自增强、有进有出保鲜。方案上，用 Tom 的引擎做 MVP（今天就能跑），用腾讯的治理与飞轮做规模化扩展。

一、两篇材料速览

腾讯文章 团队知识底座

视角：组织 / 团队级（安全中心，12+ 研发与运营 Agent）

核心命题：Agent 输出质量的上限，取决于你能给它什么质量的知识。堵点在两步——检索精度与注入效率，而非模型本身。

主线：四问定目标 → 六步搭建 → 知识飞轮 → 四条反模式

硬数据：知识 99.7% 由流程自动沉淀；代码审查从 2–4 轮降到 1.1 轮；新人上手从 30 天压到 10 天；知识月增速 86→716→154(条)。

Tom 的 wiki 个人第二大脑

视角：个人级（基于 Karpathy 的 LLM Wiki 模式）

核心命题：别"存资料"，要"养 wiki"——把碎片资料编译成结构化、互链、可增量更新的笔记，让 AI "懂你"。

主线：三层架构（RAW/Wiki/Schema）+ 三操作（Ingest/Query/Lint）+ 问答即学习闭环

硬数据：RAW 117 个原始文件 → Process 约 54 个编译页（含 14 个案例、994 条投放记录）；超 200 篇自动拆库；双周自动监测。

三、底层逻辑（7 条，且可统一）

剥掉"企业/个人""工具/平台"的外壳，两篇共同押注的是这 7 条底层逻辑：

① 知识是"供给系统"，不是"仓库"

传统知识库追求存得多；AI 时代追求匹配得准、注入得快、过时的能自动淘汰。卡点不是模型读不了长文，而是"从 2000 篇里精准捞出 2 篇"的检索精度，和"只喂相关的一段而非整篇"的注入效率。

② 结构化 + 人机共读，是检索与注入的解药

纯自然语言长文语义边界模糊，召回会漂移。结构化卡片（带适用条件、核心结论、应做/不应做）同时解决精确匹配与低 token 注入。铁律：一套知识，人和 Agent 都是消费者。人看着都莫名其妙的知识，维护质量必差、时间一长就腐败。

③ 别指望人主动写——靠流程 / 投放沉淀

腾讯：靠人写一定失败，所以把沉淀绑死在流程必经节点（需上线、已关联仓库才入池）。Tom：你只管"投喂 + 提问"，编译与蒸馏由引擎完成。共性：知识应成为流程/行为的副产品，而非额外工作。

④ 闭环 + 飞轮，是"越用越聪明"的本质

两篇都跑同一条链：生产 → 提炼 → 注入 → 消费 → 反馈 → 保鲜。腾讯的飞轮是"交付越多越厚越强"；Tom 的飞轮是"问答即学习事件，蒸馏回库"。正向循环一旦转起来，能力随使用量一起涨。

⑤ 有进有出，信噪比 > 体量

只进不出的库三个月变垃圾场。腾讯用"默认有效期 + 退场复活"防误杀；Tom 用"Lint 体检 + 增量追踪"防腐。规则：密度比体量重要，敢于"不沉淀"也能降噪。

⑥ 可观测、可追溯，才能治理

腾讯"注入即记账"、飞轮看板；Tom 的各类 log + INGEST_MANIFEST。没有度量就没有治理——每条知识被谁用了、用几次、是否过期，必须自动留痕，不靠人填报。

⑦ 先"让 AI 懂你/懂组织"，再"教 AI 做事"

奥卡姆剃刀：与其一步步教 Agent 执行，不如先构建一个它读得懂的知识底座。底层关系变了——知识的主要消费者变成 Agent 后，生产方式、质量标准、分发逻辑都要随之重构。

知识飞轮 = 沉淀(Supply) × 结构(Structure) × 反馈(Loop)
三者任一项趋近 0，系统就退化回"存资料的仓库"

四、落地方案（5 阶段路线图）

建议：从一个具体场景闭环切入，跑通再横向扩展。飞轮"开始转"比"转得快"重要。

阶段 0 · 定目标（先答四问）

  • 服务什么场景？ 锚定业务痛点（如"需求交付慢""重复踩坑"），别写"我要建知识库"。
  • 谁来消费？ 人 + Agent 都是消费者；结构要同时满足"人看得懂、Agent 查得准"。
  • 装什么？ 按 L1–L4（或 RAW/Wiki/Schema）盘点，标清责任人 + 保鲜频率。
  • 怎么算成功？ 设可观测指标：注入命中率、盲搜下降率、返工下降率、对话采纳率。

阶段 1 · 搭骨架（分层 + 三操作）

  • 三层架构：RAW（只读原始） → Wiki（结构化卡片） → Schema（规则书/宪法）。原始层坚决只读，保持证据性。
  • 三操作引擎：Ingest（摄入编译） / Query（先 INDEX 后综合） / Lint（体检）。Tom 的 py 脚本可直接复用为 MVP。
  • 知识分层：L1 公共 / L2 业务 / L3 策略 / L4 事件增量，每层明确责任人与保鲜频率。

阶段 2 · 跑通生产闭环

  • 个人/小团队：投放 RAW → 摄入引擎编译成卡片 → 自动登记进总目录。
  • 团队规模化：把沉淀绑到流程必经节点（提测通过、上线完成、事件关闭…），零人工操作。
  • 铁律：不靠人写，靠流程/投放；未达客观信号（如未上线）的知识一律暂存，不准入引用池。

阶段 3 · 分发与消费

  • 个人：查库第一站永远是总目录 INDEX.md，再定向精搜；答案自动回传留痕。
  • 团队：平台主动注入知识包（按 Agent 订阅，分仓库专属包 + 公共包，不撒网），注入即记账。
  • 飞轮钩子：把"问答"当作学习事件，好答案蒸馏回知识库（Tom 的 Learning/ 思路）。

阶段 4 · 治理与保鲜

  • 准入：双门禁（已上线 + 已关联仓库才入池）；三层质量分级（可直接用 / 待确认 / 待验证）。
  • 保鲜：默认有效期（如 90 天）重校验；零引用过期自动归档，仍有引用/被点赞则复活防误杀。
  • 体检：定期跑 Lint，查断锚/矛盾/缺失/孤儿 + 时效；人工只做高价值复核。
  • 扩展：文档超 200 篇按领域拆子库，子库之间只互链不合并，保留各自结构。

阶段 5 · 飞轮加速（规模化）

  • 贡献榜量化 + 可写进自评，但核心仍是流程自动化把活干了，别用 KPI 强压（反模式）。
  • 飞轮看板一屏可见：规模 / 质量 / 时效 / AI 调用四维度，全靠"注入即记账"自动产生。
  • 人的角色转变为"知识质量把关人"：Agent 干重复 80%，人做判断纠偏 20%。

五、今天就能跑的最小可行版（个人/小团队）

直接照 Tom 的引擎落地，零平台依赖，一个文件夹 + 三个脚本即可起步，再按需叠加腾讯的治理层：

第二大脑/
├── INDEX.md            ← 总目录（查库第一站）
├── SCHEMA.md           ← 规则书（三层/三操作/命名宪法）
├── ingest_wiki.py      ← 摄入：RAW → 结构化卡片
├── query_wiki.py       ← 查询：先 INDEX 后综合，答案回传
├── lint_wiki.py        ← 体检：断锚/矛盾/缺失/孤儿
├── Inputs/RAW/         ← 第一层：原始资料（只读，每天投喂）
├── Process/            ← 第二层：concept/entity/method/topic/case 卡片
├── Learning/           ← 问答蒸馏出的洞察（飞轮燃料）
└── Feedback/           ← 各类运行日志 + 复盘

操作节奏：日常只做两件事——把文件丢进 RAW、有问题问它；每两周跑一次 lint_wiki.py + 自动监测。其余交给引擎。团队侧要补的是：把 RAW 投喂改造成"流程节点自动沉淀"，并加上知识包主动注入与看板。

六、避坑：4 条反模式（两篇共识）

反模式后果正解
✕ 强压 KPI 逼贡献质量低、维护意愿更低流程自动沉淀为主，激励为辅
✕ 只进不出无限膨胀信噪比越来越低有效期保鲜 + 退场复活
✕ 隐性知识无法显性化专家离职带走 know-how复盘专项 + 换岗交接 + 专家萃取
✕ 人机做成两套知识维护质量差、快速腐败人机共读，一套知识库
